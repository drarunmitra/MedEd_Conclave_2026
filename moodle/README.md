# Moodle prelude course — build kit

Everything needed to build the pre-workshop Moodle course. Nothing here is
uploaded to the website.

**Live target:** SARAL 2.0, course 394 —
<https://setfacilitysaral2.org/course/view.php?id=394>
("Reproducible and AI-Augmented Medical Education Research", category *SET
Facility*).

| File | What it is |
|---|---|
| `course-blueprint.md` | Section-by-section build order, with every setting that matters |
| `activity-text.md` | The exact name and description text to paste into each activity |
| `announcements.md` | Four dated announcement posts |
| `questions/*.xml` | Six question banks, 30 questions — **the source of truth** |
| `questions/gift/*.txt` | The same banks in GIFT, generated by `xml-to-gift.ps1` — **this is what SARAL imports** |
| `xml-to-gift.ps1` | The generator. Re-run it after editing any XML |

Design rationale, and the reasoning behind the choices that look odd (no
iframes, no gating, no grades), is in
`../docs/superpowers/specs/2026-08-14-moodle-prelude-course-design.md`.

---

## ⚠ Do not move this directory under `admin/`

`_quarto.yml:18` publishes `admin/**` as a site resource. Anything in `admin/`
is copied into `_site/` and served publicly from the workshop website. Moving
the question banks there would publish the correct answers.

`moodle/` appears in neither the render list nor the resources list, which is
why it is here.

## Build order

1. Rename the four spare sections and paste their summaries —
   `course-blueprint.md` §1, text in `activity-text.md` §1.
2. Import the six question banks — see below.
3. Build sections 0 to 4 in order, top to bottom, from `course-blueprint.md`
   §2–§6, taking every name and description string from `activity-text.md`.
4. Enrol the cohort. Course 394 currently holds **8 faculty and no students**.
5. Unhide the sections. They arrive hidden from students.
6. Post announcement 1. Schedule the other three — `announcements.md` has dates.
7. Run the verification checklist below **before** the invitation email goes out.

### Importing the question banks

**Use the GIFT files, not the XML.** SARAL 2.0 does not offer the Moodle XML
format on its import screen. `xml-to-gift.ps1` converts the banks, escaping
GIFT's reserved characters and turning the true/false questions into two-option
multiple choice (the script's header explains why).

```bash
pwsh -File moodle/xml-to-gift.ps1
```

Course → *More* → **Question bank** → **Import**:

- File format: **GIFT format** — select this *before* uploading. Uploading first
  and choosing the format afterwards loses the selection and the form comes back
  with "You must supply a value here"
- Leave *Get category from file* and *Get context from file* on (they are on by
  default); the `$CATEGORY:` line in each file is what builds the tree
- Upload one file at a time:

```
questions/gift/pretest.txt                  10 questions
questions/gift/primer-01-objects.txt         4
questions/gift/primer-02-tibbles.txt         4
questions/gift/primer-03-packages-pipe.txt   4
questions/gift/primer-04-dplyr-verbs.txt     4
questions/gift/primer-05-first-plot.txt      4
                                            30 total
```

Afterwards the bank should show six categories under `Prelude`. **Done on
course 394, 14 August 2026 — all 30 imported.**

Then, for each quiz: **Add question → from question bank**, select the whole
category, and set the maximum grade to the number of questions.

## Verification checklist

Steps 1, 2 and 4 are done. The rest need a student account.

- [x] **1. Bank shape.** Every XML parses; one category element each; expected
      question count; exactly one 100%-fraction answer per question; a non-empty
      feedback on every wrong answer.
- [x] **2. Link integrity.** Every site URL named in `course-blueprint.md` and
      `activity-text.md` resolves to a real file in a built `_site/`.
- [x] **3. Preconditions.** Confirmed on SARAL 2.0 — see the table above.
- [x] **4. Import.** 30 questions across six categories under `Prelude`.
- [ ] **5. Cache measurement — settles an open question.** Open
      `prelude/primer-01-objects.html` directly in a cold browser profile with
      devtools open, and note whether `R.wasm` (12.5 MB) is fetched. Reload: it
      should not be. Now open the same page inside an iframe on another origin
      and watch again. **If `R.wasm` is re-fetched, the decision not to embed is
      confirmed. If it is not, embedding is cheaper than assumed** — record the
      result in design doc §5 either way. webR fetches inside a Web Worker, so
      watch the Network panel for the worker's requests;
      `performance.getEntriesByType('resource')` will not show them (see
      `docs/webr-verification-2026-08.md` §4).
- [ ] **6. Student dry run** on a real test account, not *Switch role to*:
      - every URL resource opens in its own window and lands on the right page;
      - one primer reaches ready and runs a cell **from the Moodle link**;
      - for each quiz, the intended answer scores 100% **and** one plausible
        wrong answer returns its specific message, not a generic one — this is
        the check that the GIFT conversion kept the per-distractor feedback;
      - the Assignment accepts pasted console text and a PNG screenshot.
- [ ] **7. Readiness report.** With the test account's work done,
      *Reports → Activity completion* shows the expected ticks and the
      Assignment submission list is scannable at cohort size.
